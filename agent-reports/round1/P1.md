## Implementation summary

### Reveal engine (`startLine` / `completeLine` / `stopTyping`)

- Replaced the 16 ms glyph interval with `requestAnimationFrame` + `performance.now()` elapsed time.
- Constants: `REVEAL_CHARS_PER_SECOND = 215`, `REVEAL_MIN_MS = 260`, `REVEAL_MAX_MS = 1000`, **hard wall-clock deadline `REVEAL_DEADLINE_MS = 950` ms**. Reveal duration is `clamp(length / 215 * 1000, 260, 1000)`; the deadline is `min(duration + 150, 950)`.
- Text is revealed with `Math.ceil(progress * length)`; the final frame writes the complete string.
- An independent `setTimeout` deadline calls `completeLine()` even if frames are throttled.
- `visibilitychange` completes the line immediately when the tab becomes hidden. On return, the full line holds until deliberate advance.
- `clearRevealTimers()` cancels both the rAF handle and the deadline timer. `stopTyping()` runs on line change, reset, panel hide, and dispose; nothing survives a restart/chapter jump.
- Narrator lines, `prefers-reduced-motion`, and empty lines call `completeLine()` synchronously (no typing class, no blips).

### Dialogue state / accessibility

- Panel classes now follow the binding contract: `is-typing` only while revealing; `is-complete` only when the full text is shown and waiting to advance; `is-narrator` for narrator lines. All three are removed when the panel hides.
- `aria-busy="true"` while revealing, `"false"` on completion, skip, hide, or immediate display.
- `#dialogue-accessible` always contains `Speaker name: full line` and has `aria-live="polite"`; `#dialogue-text` remains `aria-hidden="true"`.
- No caret after completion: the caret is CSS on `.is-typing`, and that class is removed in `completeLine()`. Measured `::after` content is `none` after completion.
- Speaker name, `--speaker-color`, and `--speaker-accent` update on every speaker change; narrator shows “Boardroom”.

### Audio

- Blips are scheduled from the reveal clock every 150 ms (well under the existing AudioEngine 95 ms cap) and only while text remains and `typing` is true.
- `blipInFlight` permits only one `AudioEngine.blip()` call at a time; resolves via both success and failure paths.
- Completion, skip, reset, and panel hide cancel the frame loop, so no new blip requests are made. Existing `AudioEngine` API only; no new audio files or API.

### Advance semantics

- A click/Space/Enter while typing calls `completeLine()` and sets `lastDialogueAdvance`, so the same gesture cannot also advance.
- A later deliberate click advances; the guard is **160 ms** (kept below the repository's existing 180 ms deliberate-click wait).
- Single-click single-advance: the root click handler, canvas click handler, and keyboard handler remain mutually exclusive; presenter/form-control guards are unchanged. No state-machine or story changes.

### P2 exit-fade hook (`is-leaving`)

- When dialogue ends, the panel removes `is-typing`/`is-complete`/`is-narrator`, sets `aria-busy="false"`, adds `is-leaving`, sets inline `pointer-events:none`, and stays mounted for 210 ms before `hidden=true`.
- A new line within the window cancels the timer, removes `is-leaving`, clears inline pointer events, and shows the panel immediately.
- `dialogueLeaving` blocks panel/canvas dialogue actions and makes `handlePrimaryKey` skip the dialogue branch during the fade, so keys/clicks reach the next screen. Reduced motion hides instantly. Timer cleared on dispose.
